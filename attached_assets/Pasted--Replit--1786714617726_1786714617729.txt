Промт для Replit

Нужно завершить серверную часть приложения и перевести пользовательские данные со статического локального хранения на серверную авторизованную систему.

Цель: пользователь должен иметь единую учетную запись, в которую можно войти с любого устройства и получить весь свой актуальный прогресс.

1. Авторизация

Настроить полноценную регистрацию и вход через Clerk.

Доступные способы:

Google;
Apple;
собственная электронная почта.

Для входа по электронной почте пароль использовать не нужно. Пользователь вводит свою почту, получает письмо с подтверждением и после подтверждения получает доступ к аккаунту.

Один пользователь, независимо от способа входа и устройства, должен иметь одну учетную запись и один набор данных.

После входа приложение должно получать текущие данные пользователя с сервера.

2. Миграция существующих пользователей

Сейчас у приложения уже есть пользователи, которые накопили данные локально в браузере.

Нужно сделать одноразовую безопасную миграцию существующего локального прогресса на сервер при первом входе.

Мигрировать нужно весь существующий пользовательский прогресс, который сейчас хранится локально: ключи, потенциал, выполненные техники, цели, историю активности и остальные существующие данные пользователя.

Особенно важно сохранить историю начислений и изменений ключей.

При миграции нельзя просто взять текущее значение баланса ключей из браузера и записать его на сервер. Сервер должен использовать существующую историю начислений/изменений, чтобы определить корректный итоговый баланс и избежать повторного начисления или дублирования уже полученных наград.

Миграция должна выполняться один раз.

После успешной миграции сервер становится основным источником пользовательских данных. Локальное хранение больше не должно использоваться как источник актуального состояния аккаунта.

Если пользователь уже прошёл миграцию, повторный вход или вход с другого устройства не должен создавать новую миграцию и изменять его данные.

3. Синхронизация между устройствами

Проверить сценарий:

Пользователь регистрируется на компьютере.
Получает свой существующий или новый прогресс.
Закрывает приложение.
Открывает приложение на другом компьютере или телефоне.
Входит в ту же учетную запись.
Видит тот же потенциал, баланс ключей, выполненные техники, цели и остальные данные.

Любое изменение пользовательского прогресса после перехода на сервер должно сохраняться на сервере и становиться доступным на других устройствах.

4. Безопасность

Пользователь должен иметь доступ только к собственным данным.

Все критические операции с прогрессом и ключами должны проверяться на сервере.

Клиент не должен иметь возможность самостоятельно изменить баланс ключей, выдать себе награду или изменить другой пользовательский прогресс через данные браузера.

5. Сохранить существующее приложение

Не менять существующую визуальную концепцию и существующие механики без необходимости.

Задача этого этапа — перевести приложение на полноценную авторизацию и серверное хранение данных, сохранив существующий пользовательский опыт.

Перед внесением изменений сначала проанализируй текущую архитектуру проекта и существующее локальное хранение. Затем предложи план изменений и только после этого приступай к реализации.

После завершения проверь основные сценарии:

новая регистрация через Google;
новая регистрация через Apple;
регистрация через email с подтверждением;
повторный вход;
вход с другого устройства;
одноразовая миграция существующего пользователя;
корректное восстановление баланса ключей по истории;
сохранение прогресса после выхода;
невозможность получить чужие данные;
невозможность повторно провести миграцию.
